# poison-snake

[Battlesnake](https://play.battlesnake.com) 에이전트예요. 행동 트리(BT), 길찾기,
강화학습(RL) 환경을 직접 만들어 보며 배우려고 시작한 프로젝트예요.

이 문서는 **무엇을 만들었고, 어떻게 돌려 보는지**에 대한 요약이에요.
설계 배경과 자세한 수치는 [영문 README](README.md)에 있어요.
뒤쪽에는 해커톤에서 바로 쓸 만한 [개념 정리](#해커톤에-쓸-개념-정리)를 붙여 뒀어요.

## 무엇이 들어 있나

```
server.py            HTTP 엔드포인트만 담당. 전략 없음
agent/world.py       게임 JSON -> World 객체 (내 뱀, 상대, 먹이)
agent/bt.py          직접 만든 행동 트리 노드 (Sequence, Selector, ...)
agent/strategy.py    decide(world) -> "up"|"down"|"left"|"right"
agent/pathfind.py    BFS 최단 경로, 플러드 필(면적 세기), 거리 지도
gym_env/rules.py     파이썬으로 다시 쓴 배틀스네이크 규칙 (시뮬레이터)
gym_env/env.py       그 규칙을 감싼 Gymnasium 환경 SnakeEnv
rl/                  MaskablePPO 학습, 평가, 학습된 모델을 뱀으로 쓰기
tools/               규칙 검증, A/B 테스트, 결정 과정 리플레이 뷰어
tests/               pytest 테스트 176개
```

## 만들어 온 순서

1. **서버**: 무작위로 자살하지 않는 수
2. **생존**: 벽·몸통·머리 충돌 회피
3. **먹이**: 체력이 낮으면 BFS로 가장 가까운 먹이
4. **공간**: 수마다 플러드 필로 면적을 재서 좁은 쪽을 피함
5. **행동 트리로 리팩터링**: 같은 판단을 트리 구조로 정리
6. **Gymnasium 환경**: 규칙을 파이썬으로 다시 구현
7. **머리 충돌 개선** → **갇힘 개선**: A/B 테스트로 검증
8. **결정 과정 뷰어**: 매 턴 판단을 HTML로 보기
9. **RL**: 커리큘럼으로 처음부터 학습

```powershell

.venv\Scripts\Activate.ps1
pip install -r requirements.txt

# 테스트
pytest -q

# 서버 (http://127.0.0.1:8000)
```

받아 `battlesnake.exe`를 이 폴더에 두고, 서버를 켠 채로 실행해요.

```powershell
battlesnake play -W 11 -H 11 --name poison --url http://127.0.0.1:8000 -g solo --browser
```

**판단 과정 보기** (서버 없이 열리는 HTML 한 장)

```powershell
python tools\explain_game.py --simulate --opponents 3 --seed 7 -o replay.html
```

수마다 왜 버려졌는지(안전/공간/탈출/최악), 영역과 면적, 행동 트리에서 어느 가지가
결정했는지를 볼 수 있어요. 숫자 키로 뱀을 바꾸고, Space/←/→로 재생해요.

**전략 A/B 테스트**

```powershell
python tools\ab_test.py "territory:*" --games 1000              # 조합 전체 선별
python tools\ab_test.py default --games 4000 --first-seed 1000  # 새 시드로 확인
```

```powershell

python -m rl.train --stage four_weak --from runs\duel_weak\model.zip --max-minutes 25
python -m rl.evaluate runs\four_weak\model.zip --stage four_weak --games 1000 --first-seed 100000
python tools\explain_game.py --simulate --agent runs\four_weak\model.zip --opponents 3 -o replay.html
```

## 결과 요약

**행동 트리 개선** (시뮬레이터 A/B, 1 vs 같은 뱀 3마리, 대등하면 25%)

| 개선 | 승률 |
|---|---|
| 머리 충돌 옵션 3개 | 22.4% → **57.6%** |
| 갇힘 옵션 3개 | 24.4% → **58.1%** [56.6, 59.6] |

**강화학습** (새 시드 평가, 총 약 63분 학습)

| 단계 | 스텝 | 결과 |
|---|---|---|
| 혼자 | 376만 | 평균 **850턴** 생존 (BT는 690턴) |
| 약한 BT 1마리 | 418만 | 승률 **67.8%** [63.0, 72.1] (대등 50%) |
| 약한 BT 3마리 | 175만 | 승률 **59.7%** [56.6, 62.7] (대등 25%) |
| 기본 BT 3마리 | 238만 | 승률 **7.6%** [6.1, 9.4] (대등 25%) |
| 기본 BT 3마리 (영역 보상 + 공간 채널, 총 9시간 학습) | 3,600만 | 승률 **35.6%** [32.7, 38.6] |

대괄호는 95% 신뢰구간이에요. 마지막 줄이 최종 모델(`runs/overnight_6/model.zip`)이고,
**옵션을 모두 켠 행동 트리 3마리를 이겨요.**

거기까지 세 가지가 필요했고, 순서가 중요했어요.

1. **영역 보상** (2.0% → 7.6% → 11.6%): 패배의 82%가 갇힘이었으니, 공간을 지키면 매 턴 보상을 줘서 그 약점을 직접 공략했어요.
2. **공간 채널** (11.6% → 12.2%, 이후 20.2%): 처음 25분에는 효과가 없어 보였는데, 학습을 더 하자 나타났어요. 그때 실패로 판단했다면 좋은 아이디어를 버렸을 거예요.
3. **시간** (20.2% → 35.6%): 밤새 30분씩 나눠 돌렸어요. 90분쯤 더 학습하자 대등한 실력(25%)을 넘었고, 3시간에 정점을 찍었어요. 그 뒤로는 좋아지지 않았어요(6시간 지점 32.1%).

구간마다 1,000판으로 점수를 냈고, 12개 중 최고를 고른 것이라 **아무도 안 쓴 새 시드로 다시 확인**했어요(36.7% → 35.6%로 유지).
갇혀 죽는 판은 82%에서 58%로 줄었어요.

# 해커톤에 쓸 개념 정리

4일짜리 게임 에이전트 대회에서 바로 꺼내 쓸 만한 것들만 추렸어요.

## 1. 행동 트리 (BT)

**무엇인가**: if-else 덩어리 대신, 판단을 트리로 조립하는 방식이에요. 노드는 네 종류면 충분해요.

- **Selector(`?`)**: 자식을 위에서부터 시도해, **처음 성공한 것**을 채택해요. "A 안 되면 B"
- **Sequence(`→`)**: 자식을 차례로 실행하고, **하나라도 실패하면 중단**해요. "A 하고 B 하고 C"
- **Condition(`◇`)**: 참/거짓만 답해요. "체력이 50 이하인가?"
- **Action(`▶`)**: 실제로 무언가 해요. "먹이 쪽으로 한 칸"

상태는 **블랙보드**(한 턴짜리 공용 메모)에 두고 노드끼리 주고받아요.
우리 트리는 `agent/bt.py`에 100줄 정도로 직접 만들었어요. 라이브러리 없이도 충분해요.

**왜 좋은가**

- **우선순위가 눈에 보여요.** 안전 → 공간 → 먹이 순서가 트리 모양 그대로예요.
- **기능을 켜고 끄기 쉬워요.** 우리는 `Options` 토글로 트리를 다르게 조립해서, 같은 코드로 여러 버전을 A/B 했어요.
- **디버깅이 쉬워요.** 어느 가지가 결정했는지 경로를 기록하면 `TURN 57 -> left [정상 턴 > 하나 고르기 > 먹기]`처럼 남아요.

**실전 팁**: "**걸러낸 뒤 고른다**"는 형태가 잘 통해요. 먼저 죽는 수를 후보에서 지우고(안전),
남은 후보를 좁히고(공간), 그중에서 목적에 맞게 하나를 골라요(먹이/영역). 목표가 늘어나도
안전 규칙을 건드리지 않아서, 새 기능이 뱀을 죽이지 않아요.

## 2. 공간을 읽는 법 (이게 승부를 갈라요)

우리 실험에서 사망 원인 1위는 언제나 **갇힘**이었어요. 쓸 만한 신호가 세 가지 있어요.

- **플러드 필 면적**: 그 수를 두면 닿을 수 있는 칸 수. 자기 몸보다 작으면 위험해요.
  싸고 간단하지만, **갇히기 한 턴 전에야** 경고해요.
- **시간을 고려한 면적**: 내가 도착할 때쯤이면 상대 꼬리가 지나가 비어 있을 칸도 세요.
  "지금은 막혔지만 곧 열리는 길"을 살려 줘요.
- **영역 (보로노이)**: 각 칸을 **누가 먼저 도착하는지**로 나눠서, 내가 먼저 닿는 칸 수를 세요.
  상대 머리들에서 한 번, 내 머리에서 한 번, 다중 시작 BFS 두 번이면 끝이에요.
  **갇히기 3~5턴 전부터 줄어들기 시작**해서 미리 대응할 수 있어요.

우리 측정값: 갇히기 1턴 전에 면적 경고는 80%가 뜨지만 그때는 이미 늦고(살릴 수 있는 수 12%),
영역 신호는 3턴 전 81%, 5턴 전 65%로 미리 경고해요.
**마지막 순간의 필터보다, 매 턴 조금씩 좋은 쪽을 고르는 점수가 낫다**는 게 결론이었어요.

## 3. 개선을 "증명"하는 법

느낌으로 고치면 대부분 헛수고예요. 우리가 쓴 방법이에요.

- **시뮬레이터를 직접 만들어요.** HTTP 없이 돌리면 초당 수천 판이라, 하루에 실험 수십 개를 할 수 있어요.
  공식 엔진 로그로 규칙이 맞는지 먼저 검증해요(우리는 CLI 게임 480판의 모든 전이를 대조).
- **1 vs 3 판수를 많이.** 새 버전 1마리를 기존 3마리와 붙여 승률을 보고, **윌슨 신뢰구간**으로
  "운인지 실력인지" 판단해요. 대등하면 25%예요.
- **시드를 분리해요.** 후보를 고른 시드로 최종 판정을 하면 **승자의 저주**에 걸려요.
  우리는 선별에서 61%였던 조합이 새 시드에서 58.1%로 내려갔어요. 3%p가 착시였던 셈이에요.
- **먼저 측정하고 고쳐요.** "왜 죽는가"를 세어 보면(머리 충돌 49% → 고친 뒤 갇힘 66%)
  고칠 곳이 저절로 정해져요.

## 4. 게임을 RL 환경으로 감싸기

`gym_env/env.py`가 예시예요. 필요한 건 다섯 가지예요.

- **관측**: 판을 그림처럼 `(채널, 높이, 너비)` 배열로. 우리는 6채널(내 머리/내 몸/상대 머리/상대 몸/먹이/체력)을 썼어요.
  **몸통 칸에는 "몇 턴 뒤 비는지"를 값으로 넣어요.** 단순히 1로 칠하는 것보다 훨씬 많은 걸 알려 줘요.
- **행동**: `Discrete(4)`처럼 작게.
- **보상**: 생존 +0.01, 먹이 +0.1, 죽음 −1, 승리 +1처럼 **가중치를 조절 가능하게** 만들어 두세요.
- **행동 마스크**: 규칙상 즉사하는 수를 아예 확률 0으로 막아요. "벽에 박으면 죽는다"를
  학습으로 배우지 않아도 되니 초반 학습이 크게 빨라져요. (`MaskablePPO`)
- **재현성**: 시드 하나로 같은 판이 반복되게. 디버깅 시간이 반으로 줄어요.

## 5. RL 학습에서 배운 것

- **커리큘럼**: 혼자 → 약한 상대 1 → 약한 상대 3 → 강한 상대 3 순으로 올리고,
  각 단계는 앞 단계 모델에서 이어 학습해요. 처음부터 강한 상대에 붙이면 거의 못 배워요.
- **보상 성형(reward shaping)**: 승패만으로는 신호가 너무 드물어요. "오래 살면 조금씩 보상",
  더 나아가 "영역을 넓게 유지하면 보상"처럼 **중간 목표**를 주면 학습이 빨라져요.
  단, 중간 보상이 본래 목표를 이기지 않도록 크기를 맞춰야 해요(우리는 생존 0.01, 영역 최대 0.02).
- **병목은 대개 GPU가 아니라 시뮬레이션이에요.** 우리는 초당 1,600스텝에서 시작해
  프로세스 간 통신을 줄여 2,200~2,700까지 올렸어요. **GPU와 CPU 어느 쪽이 빠른지는 재 봐야 알아요.**
  (작은 신경망은 GPU 왕복 비용이 더 클 수 있어요.)
- **평가는 학습에 안 쓴 시드로.** 학습 중 평가 점수는 흔들리니, 판정은 판수를 늘려 따로 해요.
- **시간 예산을 코드로 강제해요.** 단계당 25분처럼 정해 두고 자동 저장하면, 밤새 돌리다 날리는 일이 없어요.

## 6. 실수에서 얻은 것들

- **로컬 포트 고갈**: Flask 개발 서버가 매 턴 연결을 닫아서, CLI 게임을 연속으로 돌리자
  윈도우 포트가 말랐어요. `waitress`로 바꿔 해결했어요.
- **절전 시간이 학습 시간으로 계산됨**: 23분 학습이 3.4시간으로 기록됐어요.
  스텝 사이 간격이 비정상적으로 길면 세지 않도록 고쳤어요.
- **긴 학습은 세션과 함께 죽어요.** 중간 체크포인트를 자주 저장해 두면 이어서 돌릴 수 있어요.
- **매 스텝마다 프로세스에 뭔가 물어보면 느려져요.** 우리는 마스크를 따로 묻던 왕복을 없애고
  이미 받은 결과에서 꺼내 쓰는 것만으로 40% 빨라졌어요.
